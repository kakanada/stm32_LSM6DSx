# lsm6dsx — драйвер 6-осевых датчиков ST LSM6DSx для STM32

Портируемая библиотека для STM32, которая опрашивает акселерометр и гироскоп из семейства ST
LSM6DSx (LSM6DS3, LSM6DS3TR-C, LSM6DSL, LSM6DSM, LSM6DSO, LSM6DSOX, LSM6DSO32, LSM6DSR, LSM6DSRX,
ISM330DHCX) по SPI (4 либо 3 провода) или I2C, с автоматическим или ручным определением конкретной
модели и опциональной фильтрацией показаний.

## Возможности

- Единый драйвер на всё семейство LSM6DSx — конкретная модель определяется автоматически по
  регистру WHO_AM_I либо задаётся вручную в конфигурации.
- Три интерфейса подключения как runtime-параметр конфигурации (не define времени компиляции) —
  SPI 4-wire, SPI 3-wire и I2C, в том числе несколько датчиков на разных интерфейсах одновременно.
- Приоритет — быстрый неблокирующий опрос: `LSM6DSX_ReadAccel`/`LSM6DSX_ReadGyro`/`LSM6DSX_ReadRaw`
  выполняют одну короткую транзакцию по шине и не содержат циклов ожидания. Единственная
  блокирующая функция модуля — `LSM6DSX_Init`.
- Подключаемая фильтрация показаний — экспоненциальное сглаживание (минимальная задержка) либо
  скользящее среднее (лучше давит шум ценой задержки), с единой шкалой уровня 0..10, включается и
  меняется на лету через `LSM6DSX_SetFilter`.
- Поле `detected_model` в хэндле — фактически определённая модель датчика (при автопоиске) либо
  просто копия выбранной вручную модели.
- До `LSM6DSX_MAX_DEVICES` независимых экземпляров без malloc (статический пул).
- Опциональная интеграция с [stm32_logger](../../stm32_logger/git/README.md) — события
  инициализации и ошибок шины логируются через `LOGGER_Log()`, если включено
  `#define LSM6DSX_ENABLE_LOGGER` (и `#define LOGGER_ENABLE_LSM6DSX` в `logger_codes.h` проекта) —
  без этих define'ов `logger.h` не подключается вовсе, зависимость необязательна.

## Требования к настройке в CubeMX

| Интерфейс | Что настроить |
|---|---|
| SPI 4-wire | Full-Duplex Master, Data Size 8 бит, режим согласно даташиту датчика (Mode 3 обычно). Отдельный GPIO под CS как Output (High по умолчанию). |
| SPI 3-wire | Half-Duplex Master, Direction "1 Line" (`SPI_DIRECTION_1LINE`), тот же GPIO под CS, что и для 4-wire. |
| I2C | Master, Standard/Fast Mode. 7-битный адрес датчика — `0x6A` (SDO/SA0 на GND) или `0x6B` (SDO/SA0 на VDD). |

Периферию (SPI/I2C) нужно проинициализировать штатным CubeMX-кодом до вызова `LSM6DSX_Init` —
библиотека её не настраивает, только использует уже готовый хэндл.

Код, специфичный для SPI или I2C, компилируется по define'ам `HAL_SPI_MODULE_ENABLED` /
`HAL_I2C_MODULE_ENABLED` из `stm32*xx_hal_conf.h` (CubeMX сам их выставляет по включённым в проекте
периферийным модулям). Если в проекте задействован только один интерфейс — второй просто не
попадает в сборку, отсутствие соответствующего HAL-модуля не мешает компиляции.

## Быстрый старт

```c
/* SPI 4-wire, автоопределение модели */
LSM6DSX_Config_t cfg = {
    .interface      = LSM6DSX_IF_SPI4,
    .hspi           = &hspi1,
    .cs_port        = IMU_CS_GPIO_Port,
    .cs_pin         = IMU_CS_Pin,
    .model          = LSM6DSX_MODEL_AUTO,
    .xl_full_scale  = LSM6DSX_XL_FS_4G,
    .xl_odr         = LSM6DSX_ODR_104_HZ,
    .g_full_scale   = LSM6DSX_G_FS_500DPS,
    .g_odr          = LSM6DSX_ODR_104_HZ,
    .filter_type    = LSM6DSX_FILTER_EMA,
    .filter_level   = 5,
};
LSM6DSX_Handle_t *imu = LSM6DSX_Init(&cfg);
if (imu == NULL) { Error_Handler(); }

/* Определившаяся модель - для диагностики/лога */
LSM6DSX_Model_t model = imu->detected_model;

/* Основной сценарий - опрос по команде, быстро и без блокировок */
float ax, ay, az, gx, gy, gz;
LSM6DSX_ReadAccel(imu, &ax, &ay, &az);
LSM6DSX_ReadGyro(imu, &gx, &gy, &gz);
```

```c
/* I2C, модель задана вручную */
LSM6DSX_Config_t cfg_i2c = {
    .interface     = LSM6DSX_IF_I2C,
    .hi2c          = &hi2c1,
    .i2c_address   = 0x6AU,
    .model         = LSM6DSX_MODEL_LSM6DSOX,
    .xl_full_scale = LSM6DSX_XL_FS_2G,
    .xl_odr        = LSM6DSX_ODR_52_HZ,
    .g_full_scale  = LSM6DSX_G_FS_2000DPS,
    .g_odr         = LSM6DSX_ODR_52_HZ,
    .filter_type   = LSM6DSX_FILTER_NONE,
};
LSM6DSX_Handle_t *imu2 = LSM6DSX_Init(&cfg_i2c);
```

## Честные ограничения

- Не реализованы: FIFO, встроенные функции датчика (педометр, детектор наклона/стука и т.п. —
  сильно различаются между моделями семейства), self-test, режим прерываний по готовности данных
  (только опрос по команде — приоритет задачи).
- Автоопределение модели по WHO_AM_I не различает модели с одинаковым значением этого регистра
  (например, LSM6DSO/LSM6DSOX/LSM6DSO32 имеют одинаковый WHO_AM_I) — вернётся первая модель из
  внутренней таблицы; если различие критично для приложения, указывайте модель вручную.
- Таблица частот опроса (ODR) и диапазонов соответствует регистровой карте LSM6DSO/DSOX/DSR/DSRX/
  ISM330DHCX; для более ранних моделей семейства (LSM6DS3/DSL/DSM) самые высокие ODR (1.66/3.33/
  6.66 кГц) в кристалле могут отсутствовать — сверяйтесь с даташитом конкретной модели.
- Библиотека проверена ручным разбором кода и функциональным smoke-тестом на хостовой заглушке
  HAL (компилятор в среде разработки был недоступен для автоматической сборки); реальное аппаратное
  тестирование на живом датчике не проводилось.
